# 283. Move Zeroes 振り返り

## 使ったパターン
- 二つのポインタ（同じ方向に進む版）: `j` = 読む指（毎回進む）、`i` = 書く指（0 以外を見つけたときだけ進む）
- 言い換え: 「0 を後ろへ」＝「0 以外を前から詰める」

## 計算量
| | 時間 | 空間 |
|---|---|---|
| 読む指・書く指で入れ替え | O(n) | O(1) |

## つまずいた点
- 最初の方針が浮かばず、ヒント段階3（手順）まで使った
- 見方を逆にする（0 を動かす → 0 以外を詰める）のがカギだった

## 発展（操作回数を減らす）
- `i == j` のときは自分自身との入れ替えなので `if i != j` で省く → 実装済み

## 次に同じ問題を見たら
「条件を満たすものを前に詰める」= 読む指と書く指。344 の両端から近づく版とは別の形。
```ruby
i = 0
nums.each_index do |j|
  next if nums[j] == 0
  nums[i], nums[j] = nums[j], nums[i]
  i += 1
end
```

## 復習（2026-11-24）
- `/hint` なしで読む指・書く指の形を組み立て直せた
- 打ち間違い: `num[i]`（正しくは `nums[i]`）→ NameError の「Did you mean?」が答えを教えてくれる
- 条件を `nums[i] == 0 && nums[j] != 0` にしていた → 先頭が 0 以外（`[1, 0, 1]`）だと書く指 `i` がずっと止まる。テスト7個は通ったが、追加ケースで発覚
  - 書く指は「読む指が 0 以外を見つけたら **必ず** 進む」。書く指の場所の値は条件に入れない
- 入れ替えのスキップを `if nums[i] != nums[j]`（値の比較）で書いた。動きは正しいが、知りたいのは「同じ場所か」なので `if i != j` の方が意図が伝わる
