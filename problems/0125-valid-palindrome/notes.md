# 125. Valid Palindrome 振り返り

## 使ったパターン
- v1: 整える（`downcase` → `gsub(/[^a-z0-9]/, "")`）→ `reverse` と比べる
- v2（発展 / 追加メモリ O(1)）: 二つのポインタ。無視する文字のときは **片方だけ** 動かす

## 計算量
| | 時間 | 空間 |
|---|---|---|
| v1（整えて reverse） | O(n) | O(n) ← downcase / gsub / reverse は新しい文字列を作る |
| v2（二つのポインタ） | O(n) | O(1) |

- 空間は「そのメソッドが新しいものを作るか」で考える
- 1文字ずつ `s[i].downcase` するのは O(1)

## つまずいた点
- v1: 数字まで消していた（`[^a-z]`）→ `"0P"` が true になる。消すのは「英字と数字以外」
- v1 の空間を O(1) と答えた → `downcase` や `reverse` は新しい文字列を返す
- v2: `s[left] == s[left]` と打ち間違え → いつも true。false のテストだけ落ちたら比較を疑う

## 次に同じ問題を見たら
回文 = 両端から比べる。英字・数字以外は `match?(/[^a-zA-Z0-9]/)` で判定してスキップ（片方だけ動かす）。

## 復習（2026-11-23）
- 発展版（O(1)）を `/hint` なしで書けた。`if` の入れ子で「左が英数字か → 右が英数字か → 比べる」の形
- 正規表現の `[ ]` を忘れた: `/0-9A-Za-z/` は「0-9A-Za-z」という文字列そのものを探す → 1文字には絶対マッチしない → いつも true
- 正しくは `/[0-9A-Za-z]/`（`[ ]` で囲むと「この中のどれか1文字」）
