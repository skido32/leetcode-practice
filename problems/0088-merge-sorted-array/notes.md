# 88. Merge Sorted Array 振り返り

## 使ったパターン
- 二つのポインタ（2つの配列に1本ずつ）+ 書く指 = 3本の指
- **後ろから** 埋める: `nums1` の後ろは最初から空きスペースなので、大きい方から置けば未使用のデータを壊さない
  - `i = m - 1`（nums1 の本当のデータを読む）、`j = n - 1`（nums2 を読む）、`k = m + n - 1`（書く）

## 計算量
| | 時間 | 空間 |
|---|---|---|
| 後ろから3本の指 | O(m + n) | O(1) |

## つまずいた点
- 最初は nums2 を後ろにくっつけただけ（並べ替えが残る）→ 「両方とも並んでいる」条件を使う
- 前から書くと未使用の nums1 を上書きしてしまう → 後ろから書く（ヒント段階3まで使った）
- `j > 0` / `i > 0` → 0番目も残っているデータ。正しくは `>= 0`（off-by-one）
- ブロック変数 `|n, i|` がメソッド引数 `n` と同じ名前になっていた

## 次に同じ問題を見たら
2つの並んだ配列を合体 = 先頭（または末尾）どうしを比べて選んだ方だけ進める。in-place で後ろに空きがあるなら **後ろから大きい方を置く**。
ループは「nums2 が残っている間」（`while j >= 0`）。nums1 の残りは最初から正しい位置にある。

## 復習（2026-11-25）
- `/hint` なしで解けた。「後ろから大きい方を置く」と `while j >= 0` は最初から書けた
- 打ち間違い: `nums[i]`（正しくは `nums1[i]` / `nums2[j]`）→ 283 復習の `num` と同じ。NameError の `Did you mean?` を見る
- `if i > j` と **番号どうし** を比べていた → 比べるのは **値**（`nums1[i] > nums2[j]`）
- `i >= 0 &&` を忘れた → `i` がマイナスになっても `nums1[-1]` は最後の要素を返すのでエラーにならず、最後は `nil > ...` で落ちる
  - 「片方の配列を使い切ったか」のチェックは、値の比較より **先に** 書く
