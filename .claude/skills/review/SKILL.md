# 解答レビュー

1. 対象の問題を特定し、`README.md`・`solution.rb`・`test_solution.rb` を読む。`bin/t <番号>` を実行する。
2. **テストが落ちる場合**: 修正コードは書かない。失敗しているケースを示し、「この入力のとき、変数は各ステップでどうなる？」と問いかけてデバッグを促す。必要なら `/hint` の段階1〜2程度の示唆まで。ここで終了。
3. **テストが通る場合**:
   a. 自分でも追加のエッジケースを2〜3個考え、`ruby -e` などで試す（テストファイルには勝手に追加せず、落ちたら学習者に伝える）。
   b. 学習者に「時間計算量と空間計算量は？」と聞く。**答えを待ってから**正誤と理由を説明する。
   c. 回答後に講評: 良い点 / 読みやすさ・Rubyらしさ（`each_with_index`, `Hash.new(0)`, `tally` など）/ より良い計算量の解法があればその考え方。ここではコード例を見せてよい。
   d. 面接を想定し、「この解法を30秒で説明して」と口頭説明の練習を1回促す。
4. 振り返りを記録:
   - `notes.md` を学習者と一緒に埋める（パターン・計算量・つまずき・次に見たら何を思い出すか）。学習者の言葉を優先。
   - `progress.md` に1行追加（日付は今日、結果は「自力 / ヒントあり / 答えを見た」、所要時間は学習者に聞く）。
   - `roadmap.md` の該当問題を `[x]`（自力）または `[~]`（ヒント・答えあり）に更新。
   - `patterns.md` を更新: 新しいパターンなら「サイン → パターン」の表に1行追加（既存なら問題番号を足す）。新しい計算量の罠・Ruby のハマりどころがあれば追記。
5. **コミットして push する**（学習者の了承済み。毎回確認しなくてよい）:
   - 対象: その問題のフォルダ（`problems/NNNN-slug/`）と、更新した `progress.md`・`roadmap.md`・`patterns.md`。それ以外の未コミットの変更は勝手に含めず、あれば一言伝える。
   - コミットメッセージ: 1行目は `solve: NNNN Title`（復習なら `review: NNNN Title`）。本文に「結果（自力 / ヒントあり / 答えを見た）」「時間・空間計算量」「つまずいた点を1行」。末尾にはそのセッションで指定された署名行（Co-Authored-By など）を付ける。
   - `git push` する。失敗したら（認証切れ・リモートの変更など）原因を伝え、勝手に force push などはしない。
   - 完了したら、GitHub のコミット URL を1行で伝える。
6. 最後に「LeetCode にも提出してみよう」と、`solution.rb` の中身をそのまま貼れば通ることを伝え、`/next` を案内する。
